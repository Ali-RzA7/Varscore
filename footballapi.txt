iSportsAPI Entegrasyon Dokümanı: Canlı Skor ve İstatistik Yönetimi
Bu doküman, mobil uygulamada futbol maçlarının gün bazlı fikstürlerini, detaylı istatistiklerini ve anlık (canlı) skor değişikliklerini iSportsAPI üzerinden çekmek için gereken uçları (endpoint) ve mimari akışları açıklamaktadır.

1. Temel Bağlantı Bilgileri
Base URL: [http://api.isportsapi.com/sport/football/](http://api.isportsapi.com/sport/football/)

Yetkilendirme: Tüm isteklere api_key parametresi eklenmek zorundadır.

Veri Formatı: JSON

2. Gün Bazlı Filtreleme ve Fikstür Çekme
Kullanıcının uygulamada takvimden seçtiği bir güne ait maçları (geçmiş, bugün veya gelecek) ve o maçların detaylı istatistiklerini çekmek için kullanılır.

Endpoint: /schedule (Detaylı Fikstür)

HTTP Metodu: GET

Parametreler:

api_key (Zorunlu)

date (İsteğe Bağlı): YYYY-MM-DD formatında (Örn: 2026-05-02). Girilmezse bugünün verisini döndürür. Geçmiş 1 aya kadar sorgulama yapılabilir.

Kullanım Senaryosu:
Kullanıcı ana sayfada "Dün" sekmesine tıkladığında veya takvimden bir tarih seçtiğinde bu uca istek atılır. Dönen liste uygulamanın arayüzünde (RecyclerView) listelenir.

Örnek JSON Çıktısı (Özet):

JSON
{
  "matchId": "123456",
  "leagueName": "Turkey Super League",
  "homeName": "Fenerbahce",
  "awayName": "Galatasaray",
  "homeScore": 2,
  "awayScore": 1,
  "status": -1, 
  "homeRed": 0,
  "homeYellow": 3,
  "homeCorner": 6
}
(Not: status: -1 maçın bittiğini gösterir.)

3. İstatistik Yönetimi
Maç istatistikleri ayrı bir uçtan değil, yukarıda belirtilen /schedule ucundan dönen JSON paketinin içerisinde dâhili olarak gelmektedir.

Mobil arayüzdeki "Maç Detay" sayfasında (UI) gösterilecek anahtar kelimeler şunlardır:

Skorlar: homeScore, awayScore

İlk Yarı Skorları: homeHalfScore, awayHalfScore

Kartlar: homeRed, awayRed, homeYellow, awayYellow

Kornerler: homeCorner, awayCorner

Uzatma Dakikası: injuryTime (Örn: +4 dk)

İlk 11 Durumu: hasLineup (Eğer true ise arayüzde "Kadroları Gör" butonu aktif edilebilir).

4. Canlı Skor Akışı (Live Scores)
Canlı skor mimarisi, API limitlerini tüketmemek ve performansı artırmak adına iki aşamalı kurgulanmalıdır.

Adım 4.1: Günün Temel Verisini Çekme
Endpoint: /livescores

Bu uç günde veya uygulama ilk açıldığında sadece 1 kez çağrılır.

Amacı: O gün oynanan/oynanacak tüm maçların matchId ve takım isimlerini (homeName, awayName) çekip mobil cihazın lokal veritabanına (Room) kaydetmektir.

Adım 4.2: Sadece Değişiklikleri Dinleme (Polling)
Endpoint: /livescores/changes

Çalışma Mantığı: Bu uç, sadece son 20 saniye içinde gol olan, kart çıkan veya durumu değişen maçları döndürür. Değişiklik yoksa boş döner.

Önerilen İstek Sıklığı: Her 10 veya 15 saniyede bir çağrılmalıdır.

Sistem Akışı:

Mobil uygulama 15 saniyede bir /livescores/changes ucuna istek atar.

Fenerbahçe maçında gol olur ve API şu yanıtı döner: {"matchId": "123", "homeScore": 1}.

Uygulama, 123 ID'li maçın takım isimlerini Adım 4.1'de kaydettiği lokal veritabanından bulur.

Ekranda o maça ait satır güncellenir ve "Gol" animasyonu çalıştırılır.

5. Mobil Geliştirme İçin Kritik Uyarılar ve Tavsiyeler (Best Practices)
Lokal Önbellekleme (Caching): Geçmiş günlerin maç sonuçları (/schedule) bir kez çekildikten sonra SQLite/Room veritabanına kaydedilmelidir. Kullanıcı aynı geçmiş güne tekrar tıkladığında API'ye gitmek yerine veri lokalden hızlıca getirilmelidir. Bu, API limitlerini korur.

Sayfa Odaklı Polling: Canlı skor dinleme (/livescores/changes) işlemi sadece kullanıcı "Canlı" sekmesindeyken çalışmalı, uygulama arka plana atıldığında veya başka sayfaya geçildiğinde istek atma işlemi (Timer/Coroutine) durdurulmalıdır.

Basic vs Schedule Farkı: Kullanıcıya çok sayıda maçın listelendiği genel fikstür ekranlarında ağı yormamak için kart ve korner gibi verilerin olmadığı /schedule/basic ucu kullanılmalıdır. Kullanıcı bir maça tıkladığında detaylı /schedule verisi çekilmelidir.

Güvenlik: api_key parametresi mobil uygulamanın kaynak kodlarına açıkça (hardcoded) yazılmamalıdır. local.properties dosyası veya bir sunucu (Backend) üzerinden güvenli bir şekilde alınmalıdır.

Schedule & Results
Update Time: 2026-04-02 05:23Change Log

Introduction
• This API endpoint returns the results of a specified date, event or match.

• One of the three parameters "date", "leagueId", and "matchId" is required, and the three parameters cannot be used at the same time.

• You can use it with the Match Modify Record endpoint.

Related Plans
You can use this api by subscribing plans:  Live Data.

Request
Path: /sport/football/schedule
Method: GET
Calls: This interface is limited to 60 second/call;
Recommend Calls: 12 hour/call
Parameters: The request path needs at least one parameter (date, leagueId, and matchId ) to retrieve correct response. These three parameters can not be used at the same time.

date	string	false	yyyy-mm-dd, e.g. 2019-08-01.
Return the match data of the specified date, the range is GMT+0 0:00-23:59; The historical schedule data is limited to query the past month.

stageId	string	false	Use with leagueId to get the specified cup stage.
matchId	string	false	Multiple matches can be requested at the same time, and "matchId" is separated by ",", and a maximum of 100 matches can be queried at a time.

import java.io.BufferedReader;
import java.io.InputStream;
import java.io.InputStreamReader;
import java.net.HttpURLConnection;
import java.net.URL;

public class SportDemo {
  public static void main(String[] args) {
    // Set url parameter
    String url = "http://api.isportsapi.com/sport/football/schedule?api_key=<YOUR_API_KEY>&leagueId=1639";

    // Call iSport Api to get data in json format
    String charset = "UTF-8";
    String jsonResult = get(url, charset);

        System.out.println(jsonResult);
  }

  /**
   * @param url
   * @param charset
   * @return return json string
   */
  public static String get(String url, String charset) {
    BufferedReader reader = null;
    String result = null;
    StringBuffer sbf = new StringBuffer();
    String userAgent = "Mozilla/5.0 (Windows NT 6.1) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/29.0.1547.66 Safari/537.36";
    try {
      URL newUrl = new URL(url);
      HttpURLConnection connection = (HttpURLConnection)newUrl.openConnection();
      connection.setRequestMethod("GET");
      connection.setReadTimeout(30000);
      connection.setConnectTimeout(30000);
      connection.setRequestProperty("User-agent", userAgent);
      connection.connect();
      InputStream is = connection.getInputStream();
      reader = new BufferedReader(new InputStreamReader(is, charset));
      String strRead = null;
      while ((strRead = reader.readLine()) != null) {
        sbf.append(strRead);
        sbf.append("\r\n");
      }
      reader.close();
      result = sbf.toString();
    } catch (Exception e) {
      e.printStackTrace();
    }
    return result;
  }
}
